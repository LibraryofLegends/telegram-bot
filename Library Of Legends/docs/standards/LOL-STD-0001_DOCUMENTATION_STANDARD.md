# 1. Purpose

This standard defines the mandatory rules for creating and maintaining documentation within the Library Of Legends project.

Its objective is to ensure that every document follows the same structure, terminology and quality expectations.

---

# 2. Scope

This standard applies to all project documentation, including:

- Foundation
- Standards
- Policies
- Workflows
- Architecture
- Specifications
- Module Documentation
- API Documentation
- Technical References

---

# 3. Documentation Philosophy

Documentation is considered part of the software.

Every document shall:

- remain accurate
- remain understandable
- remain consistent
- evolve together with the implementation

Documentation shall never become outdated intentionally.

---

# 4. Mandatory Document Structure

Every official document shall contain:

- Title
- Document Metadata
- Table of Contents
- Main Sections
- Practical Impact
- Related Documents
- Revision History
- Approval Block

No required section may be omitted without architectural approval.

---

# 5. Writing Rules

Documentation shall:

- use clear language
- avoid ambiguity
- describe responsibilities
- avoid duplication
- remain technically accurate
- prioritize readability

---

# 6. Formatting Rules

Every document shall use:

- Markdown
- Consistent heading hierarchy
- Standardized tables
- Ordered sections
- Uniform terminology

Formatting shall remain identical across the repository.

---

# 7. Naming Rules

Every document shall follow the approved naming convention.

Examples:

LOL-DOC-0001_PROJECT_CHARTER.md

LOL-STD-0001_DOCUMENTATION_STANDARD.md

LOL-POL-0001_DEVELOPMENT_POLICY.md

LOL-WF-0001_DEVELOPMENT_WORKFLOW.md

---

# 8. Quality Requirements

Before approval every document shall be reviewed for:

- Completeness
- Accuracy
- Consistency
- Grammar
- Formatting
- Architectural Compliance

---

# 9. Practical Impact

This standard applies to every documentation category within the repository.

Affected Areas

- docs/foundation/
- docs/standards/
- docs/policies/
- docs/workflows/
- docs/architecture/
- docs/specifications/
