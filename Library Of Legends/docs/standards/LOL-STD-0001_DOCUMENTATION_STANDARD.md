# LOL-STD-0001 — Documentation Standard

## 1. Executive Summary

This document defines the official documentation standard for every document created within the Library Of Legends project.

Its purpose is to ensure consistency, readability and long-term maintainability across the entire documentation.

Every project document shall comply with this standard.

---

## 2. Documentation Philosophy

Documentation is part of the software.

A feature is not considered complete until its documentation has been reviewed and approved.

Documentation shall always explain **why**, **what**, and **how**.

---

## 3. Standard Document Structure

Every official document shall follow the same structure.

| Section | Required |
|---|---|
| Document Header | ✅ |
| Metadata Table | ✅ |
| Executive Summary | ✅ |
| Main Content | ✅ |
| Related Documents | ✅ |
| Revision History | ✅ |
| Approval | ✅ |
| End of Document | ✅ |

## 5. Heading Structure

The following heading hierarchy shall be used.

```text
# Document Title

## Main Chapter

### Section

#### Subsection
```

Heading levels shall never be skipped.

---

## 6. Tables

Tables shall be used whenever structured information is presented.

Examples include:

- Metadata
- Revision History
- Dependencies
- Responsibilities
- Approval
- Related Documents

Tables improve readability on desktop and mobile devices.

---

## 7. Lists

Use numbered lists for ordered processes.

Use bullet lists for unordered information.

Avoid deeply nested lists whenever possible.

---

## 8. Writing Style

Documentation shall be:

- concise
- precise
- technically accurate
- consistent
- future-oriented

Avoid unnecessary repetition.

Use professional terminology.

---

## 9. Language

English is the official documentation language.

German may be used during discussions but not in official project documentation.

---

## 10. Cross References

Whenever possible, documents shall reference related documentation.

Example:

| Document ID | Description |
|---|---|
| LOL-DOC-0001 | Project Charter |
| LOL-DOC-0002 | Library Blueprint |

---

## 11. Revision History

Every document shall maintain a revision history.

| Version | Description |
|---|---|
| Major | Structural changes |
| Minor | New content |
| Patch | Corrections |

---

## 12. Approval

Every official document requires an approval section.

Approval confirms that the document complies with the current project standards.

---

## 13. Future Compatibility

This standard shall evolve without breaking previously approved documentation whenever possible.

Major changes require a new document version.
