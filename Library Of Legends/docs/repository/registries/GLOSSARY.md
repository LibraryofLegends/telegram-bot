# 1. Purpose

The Glossary is the official and authoritative dictionary of terminology used throughout the Library Of Legends Architecture Framework (LOAF).

Its purpose is to establish a consistent vocabulary for developers, architects, contributors and maintainers.

Every technical, architectural and organizational term used within the project shall have one official definition.

---

# 2. Scope

The Glossary includes terminology related to:

- Architecture
- Documentation
- Development
- Databases
- APIs
- Modules
- Packages
- Assets
- Templates
- Telegram
- Operations
- Security
- Quality Assurance
- Governance

The Glossary shall evolve together with the framework.

---

# 3. Glossary Governance

Every definition shall be:

- unique
- unambiguous
- reviewed
- maintained
- version controlled

Duplicate definitions are prohibited.

Whenever terminology changes, the Glossary shall be updated before implementation.

---

# 4. Naming Conventions

Official naming rules include:

- PascalCase for Classes
- camelCase for Variables
- kebab-case for File Names (where applicable)
- UPPER_SNAKE_CASE for Constants
- Semantic Versioning for Releases

All naming conventions shall comply with LLCS.

# 6. Technical Terms

## API

A defined communication interface between software systems.

---

## Asset

A reusable digital resource such as an image, icon, logo, banner, font, audio file or video.

---

## Component

A reusable implementation unit that provides a specific capability.

---

## Database

A persistent storage system containing structured information.

---

## Dependency

A relationship where one object requires another object to function correctly.

---

## Framework

A structured collection of principles, standards, specifications and reusable components.

---

## Metadata

Structured information describing another object.

---

## Module

A functional business capability within the system.

---

## Package

A logical collection of related modules, libraries or components.

---

## Registry

The authoritative inventory of a specific object type.

---

## Repository

The complete source tree of the project.

---

## Specification

A detailed technical description of implementation requirements.

---

## Standard

A mandatory rule defining how work shall be performed.

---

## Template

A reusable predefined structure for documents, code or configurations.

---

# 7. Architecture Terms

## Architecture

The structural design of the complete software system.

---

## Architecture Decision Record (ADR)

A documented architectural decision together with its context and consequences.

---

## Governance

The collection of rules controlling architecture, documentation and development.

---

## Object

Any uniquely identifiable entity managed by LOAF.

---

## Object Identifier

A permanent identifier assigned to an architectural object.

Example:

OBJ-MOD-0001

---

# 8. Documentation Terms

## Document

An officially managed information artifact.

---

## Document ID

A permanent identifier assigned to documentation.

Example:

LOL-REG-0010

---

## Version

The current released revision of an object or document.

---

## Revision

A documented modification of an existing version.

---

# 9. Repository Terms

## Repository Root

The highest directory within the project.

---

## Package Directory

A directory containing reusable software packages.

---

## Module Directory

A directory containing implementation modules.

---

## Documentation Directory

The location of all official project documentation.
