# 1. Purpose

This guide defines how documentation is created, maintained and reviewed within the Library Of Legends project.

It serves as the authoritative guide for all project documentation.

---

# 2. Documentation Philosophy

Library Of Legends follows a Documentation First approach.

Documentation is considered part of the software.

Every architectural decision, feature, module and release shall be documented.

Documentation must evolve together with implementation.

---

# 3. Documentation Collections

The documentation is organized into the following collections:

- Foundation
- Governance
- Standards
- Architecture
- ADR
- Reference
- Modules
- Database
- API
- Telegram
- Media
- Testing
- Releases

Each collection has a defined purpose and scope.

---

# 4. Document Lifecycle

Every document follows this lifecycle:

1. Planned
2. Draft
3. Review
4. Stable
5. Deprecated
6. Archived

The current status shall always be visible in the document metadata.

---

# 5. Required Document Structure

Every official document shall contain:

- Document Header
- Document Metadata
- Table of Contents
- Main Content
- Definition of Ready
- Definition of Done
- References
- Related Documents
- Revision History
- Document Change Log
- Approval Block

No mandatory section may be omitted.

---

# 6. Naming Conventions

Document names shall:

- use uppercase letters where established
- remain descriptive
- avoid abbreviations unless officially defined
- remain unique

Every document shall have a unique Document ID.

---

# 7. Versioning Rules

Each document has its own version.

Project version and document version are managed independently.

Versioning follows Semantic Versioning where applicable.

---

# 8. Review Process

Before a document reaches Stable status, it shall be reviewed for:

- Accuracy
- Consistency
- Formatting
- Cross references
- Grammar
- Compliance with LLDS

---

# 9. Quality Requirements

Documentation shall be:

- Complete
- Understandable
- Up-to-date
- Consistent
- Verifiable
- Traceable

Quality reviews shall be documented.

---

# 10. Definition of Ready

A document is ready when:

☑ Purpose defined

☑ Scope documented

☑ Metadata complete

☑ Document ID assigned

☑ Related documents identified

---

# 11. Definition of Done

A document is complete when:

☑ Content finalized

☑ Formatting verified

☑ References validated

☑ Review completed

☑ Approved

☑ Registered in PROJECT_INDEX
